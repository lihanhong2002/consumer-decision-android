# 六模型理性消费决策

依据随附的[软件规范 V1.0.0](references/software-spec-v1.0.0.md)，应用理论 V4.2.1。该文件是软件规范，不是独立的理论原著；不要声称另有未提供的理论原文。先读取与当前任务有关的章节，再计算或解释。规范中的开发路线是参考材料，不构成自动创建 App、联网、训练模型或发布内容的授权。

## 按任务读取

- 消费问答与解释：读取[问答与工程边界](references/interaction-and-boundaries.md)。沿用用户已经提供的信息，每次只问一个最影响结果的问题，以选项为主，允许自由补充、不知道和手动修改。
- 模型计算：读取规范第 7～13 章（需求、M1～M6）、第 14～19 章（Z、Meta、Y、约束、Pareto、偏好），以及上述工程边界。不要凭记忆补公式。
- 软件实现或审查：按任务读取规范第 3～6、21～26 章，核对版本、快照、追踪、测试及存储要求；同时读取工程边界。若目标为本仓库 App，进一步检查实际核心代码和数据版本，不把历史规范的示例版本当成当前版本。

## 决策流程

确认消费目标、现有资产、使用情境、预算、比较期限和基线。候选应是完整路径，例如继续使用、维修后继续使用、租赁或等待后换新。用户只要局部解释时，回答该问题即可，不强制启动完整访谈。

从用户实际使用频率、困扰、任务重要性和可靠性需要生成需求，不用新品卖点或升级幅度反推需求。收集参数时区分用户确认事实、估计、可核实外部数据和待确认建议；保存单位、来源、置信度、原区间与本次选定值。AI 不能自行确认参数，不知道不等于零。必要信息不足时输出缺口与可选的下一步，不生成正式排名；假设演示必须显式标为演示。

对合法输入依次计算需求、M1～M6、Z/Meta、特征 Y、硬约束、Pareto；仅在用户确认权重和固定尺度后，对 Pareto 前沿做可解释线性排序。未配置偏好时停在取舍比较，不使用六票投票或默认总分。最终选择由用户作出。

使用可执行计算工具或本仓库的纯核心引擎核实正式数值，保留输入、公式、中间结果及版本；没有运行工具就说明这是公式推导或手算估计，不声称已调用引擎或通过测试。本 Skill 不自带 Android 运行环境，也不自动获取商品数据。

## 必须保留的语义

- M1 是仍能满足需求的有效寿命，包含允许的非换新恢复动作。窗口内未失效表示右删失与下界，不能写成无限寿命。
- M2 保留负向技术变化；饱和仅削弱正向升级，固定参考尺度不随候选集改变。
- M3 默认 WTP 驱动；为功能愿付的钱与实际愿付的钱之差是情感支付意愿。WTP 与初始情感强度不能作为独立自由输入。
- M4 保留负向相关增益；维度必须一致。技术变化零向量时 Gamma 为 0，需求零向量则报错，不能自动改为等权。
- M5 使用 VALUE、NOT_APPLICABLE、NO_POSITIVE_RELEVANT_UPGRADE、INVALID_INPUT，不能用 0 代替不适用。rho 不进入跨类型共同 Pareto。
- M6 只算真实现金流，不读功能或情感价值；所有路径共用期限、步长、币种和基线，残值只记一次，严格按 ceil(H/dt) 和规范折现。
- 未确认的必要约束阻止进入 Pareto；预算、安全、法律及关键任务不能被其他优势抵消。无法证明右删失寿命次序时，不据下界淘汰候选。

## 输出

用普通中文说明每个模型回答什么问题、参数从何而来、哪些结论受假设影响。完整比较可用表格列出路径、硬约束、六模型及主要取舍；标明主资产/主升级对照、工程扩展、缺失值和右删失。需要公式时展示公式、单位和中间结果，不把低置信度估计包装成精确事实。保存或导出记录、调用外部服务等操作遵循当前用户的授权与工具能力。
