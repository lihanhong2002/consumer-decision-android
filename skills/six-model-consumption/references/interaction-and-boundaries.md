# 问答与工程边界

## 材料与版本

随附 `software-spec-v1.0.0.md` 是本仓库 `docs/reference/Software_Spec_V1_0.md` 的原样副本，理论依赖固定为 V4.2.1。为使技能目录单独复制后仍可使用，附完整规范和 MIT 许可证。维护时同步两份规范；不要把本文件中的工程约定当作理论原著新增的定理。

软件规范第 21 章展示 `evaluate(caseId)` 分层示意；本仓库实际核心入口是 `DecisionEngine.evaluate(inputSnapshot, config)`，加载数据和保存时间戳由应用层负责。备份、Room、应用和引擎版本是不同概念：检查当前代码与 README，不照抄旧工程记录的版本号。

## 面向普通用户的提问

只问当前还缺、并且会影响比较的信息，先收集目标与底线，再问计算参数。允许随时切换手动填写。已有答案可复用，但旧参数是否适用于新情境仍须确认。选项里的金额、使用频率或时间范围是辅助表达，不是已校准系数。

| 模型/概念 | 通俗解释 | 可用问题示例 |
|---|---|---|
| 比较期限 H | 这次打算比较未来多久 | “你想比较未来多久：1 年、3 年、5 年，还是自己填写？” |
| 需求权重 d | 哪些用途对你更重要 | “你最不能忍的是：续航不够、速度慢、拍照差，还是没有明显困扰？”随后确认各用途权重，不能仅凭此题生成完整向量。 |
| M1 有效寿命 | 考虑可行维修后，还能满足需求多久 | “哪些情况出现时，你会觉得它已经不能用了？” |
| M2 技术变化 | 升级和退步有多少，你能否感受到 | “新方案哪些方面改善、哪些方面变差？不知道可以先空着。” |
| M3 情感支付意愿 | 单纯因为喜欢，愿意额外付多少 | “如果功能完全一样，你会为喜欢的外观或品牌多花多少？可选 0、自己填写、不知道。” |
| M4 需求对齐 | 改善是否落在你在意的用途上 | “这些改善里，哪项能解决你实际遇到的问题？” |
| M5 rho | 在适用的升级比较里，涨价相对有效提升是否划算 | “和哪个明确基准相比，价格多了多少？”不存在升级对照时直接解释不适用。 |
| M6 现金流现值 | 在同样期限下，把实际支出与收入折算到今天比较 | “除了购买费用，还会有维修、租金、耗材或出售收入吗？” |
| 折现率 r | 未来的钱按什么比例折算到今天 | 说明可由用户选定；若提出假设，显示依据并等待确认，不能默认称为科学值。 |
| 右删失 | 比较期结束仍能用，只知道至少能用到这里 | “三年内没发现失效”不等于“恰好只能用三年”。 |
| Pareto | 不能在所有比较指标上同时被另一个方案赶超的方案集合 | 表示各有取舍，不能称为唯一推荐或自动最优答案。 |

规范中的饱和锚点 0.80、情感衰减初始化示例等不是对所有人的经验事实。乘法指数、加权系数、参考尺度、感知阈值、衰减参数和偏好权重均须有来源；个人参数须确认。区间估计先保留区间，正式计算须明确选择合法标量；做敏感性分析时分别标注各情景，不用区间中点悄悄代替输入。

## App 的显式工程扩展

- `path-projection-1`：保留全部资产与升级事件的 M1～M5，用户指定主资产和主升级对照形成策略级 Z。M1 评估主资产自阶段开始后的剩余寿命，窗口统一为 H；主情感来自该阶段，迭代、对齐与 rho 来自主对照。各阶段寿命、迭代或情感不自行相加；M6 覆盖整条路径。切换主对照不改变现金流。
- 服务阶段覆盖 `[0,H]`，同一资产不能重叠。维修恢复当前状态，换新建立新身份。任何阶段的服务失败不能被后续换新掩盖。同身份相邻阶段效用连续；费用通过事件关联只记一次。
- 初始归一化效用和维修后分段衰减是工程扩展，要在追踪中说明。维修恢复为 `u + q(1-u)`；替换核心身份的动作不能作为非换新维修延长同一资产寿命。
- M1 默认步长为 1/12 年，额外检查需求变更、维修和窗口终点；需求按用户侧时间节点分段保持。年/月单位统一后再计算。
- M5 本 App 进一步要求增量价格为正，这是实现策略。缺少合法基准或正相关升级时保留相应状态，不制造可比较数值。
- M6 事件归入发生时点之后的首个格（恰在格点归该格），零时点归初始现金流，H 时点残值归第 N 格。非整步长尾段也按规范第 N 格折现，不自行改变规则。
- 默认预算只限制零时点实际支出；可另设全期累计支出上限，不以收入或残值抵消。必要的服务、安全、法律、关键任务及自定义条件未确认时，结果只能作为草稿。
- 共同 Pareto 使用寿命、I_personal、情感 WTP、Gamma 和现金流差值五项。寿命使用精确值或 `[下界,+∞)` 的区间语义：只能在能证明全部指标不差且至少一项严格更好时判支配；两个右删失下界的大小不能证明其真实寿命次序。
- `psi-1` 默认特征是寿命、情感 WTP、G_rel 和现金流差值。偏好排序只在 Pareto 前沿运行，权重和固定参考尺度须经用户确认；用右删失下界参与排序须明确说明这一假设。添加候选不能改变原策略的模型计算值。

## 可追溯结果

区分未知、不适用、尚未收集、理论未定义及输入错误。保存原始输入、选定标量、来源、置信度、计算配置、全部中间结果和版本。金额使用十进制字符串与币种；正式输入稳定序列化后保存 SHA-256。修改后重新计算生成新快照，保留旧记录。与 App 互操作时依实际 schema 校验，勿凭规范示例拼造可导入文件。

例如用户只说“预算 3000，手机续航差”，下一题可以问“你更想：继续用、换电池、换新机，还是先看看几种方案？”；此时还缺维修恢复程度、各路径费用、任务底线及时间窗，不能立即输出精确寿命或宣称换新最优。
